# Iteration 00 — Engineering Foundation and Cashflow Slice

**Date:** 2026-11-03
**Status:** Implemented locally; 11 tests and local HTTP smoke test recorded as passing; remote push not confirmed.
**Branch:** `iteration/00-engineering-foundation`

## Goal

Create a clean, testable starting point and implement one real, deterministic financial domain vertical slice rather than generating a broad set of unconnected UI or AI placeholders.

## Scope delivered

- Python 3.12+ package and FastAPI app.
- Modular separation of HTTP API, application use case and pure domain logic.
- Health and readiness endpoints.
- Request/response schemas and boundary validation.
- Exact decimal money helpers and a curated currency exponent table.
- Period cashflow calculator for caller-supplied income and expense entries.
- Unit/API tests, Ruff configuration, GitHub Actions, Dockerfile, Makefile and engineering documentation.

## Main request path

`POST /api/v1/cashflow/analyze` -> Pydantic validation -> `run_cashflow_analysis` -> `analyze_cashflow` -> `quantize_amount` / `quantize_total` -> response DTO.

## Accepted domain rules

- Amounts are positive and finite; precision must match supported currency minor units.
- All entries must lie inside the inclusive requested period.
- Period end cannot be earlier than period start.
- Expense entries are partitioned into essential and discretionary groups.
- Category totals are sorted by descending amount, then category case-insensitively.
- Net cashflow = income total - expense total.
- Current `savings_rate_percent` = net cashflow / income total * 100; `None` when income is zero. It is not proof of actual savings.

No persistence, identity, consent, bank data import, authentication, authorization, payment, AI model, agent, RAG, graph, benefits or merchant integration. No real-world financial outcome was generated by this slice.
