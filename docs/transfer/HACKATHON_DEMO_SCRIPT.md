# AwnNORA — Judging Demo Script

## Before the presentation

1. Run the Python API and TypeScript web application locally.
2. Create and verify one dedicated synthetic demo account.
3. Seed synthetic persona `CUS00001` using the first-user runbook.
4. Configure the server-side `MODEL_API_KEY` and confirm one actual Muse Spark Standard-mode call from the AI intelligence screen. If this cannot be done, do not claim a live Meta API integration; show the architecture and the explicit unavailable state instead.
5. Keep external provider, payment, bank, benefit and settlement connections disabled.
6. Make sure the UI clearly displays `SYNTHETIC DEMO` or `PRIVATE ACCOUNT` at all times.

## Suggested 4-minute flow

### 0:00–0:35 — The economic problem

Explain structural asymmetry: institutions have analysts, procurement, legal and negotiation capacity; ordinary households do not. AwnNORA gives the individual a private economic representative. It is not just a budget tracker or chatbot.

### 0:35–1:20 — One-person Day-One value

Open the synthetic demo overview. Point to classified inflow/outflow, upcoming essential obligations, the duplicate candidate and the explicit `₹0` verified value. Explain that this first slice works for one user without Commons and without mandatory bank linking. Connect the local account and refresh to show the same report through the authenticated API.

### 1:20–2:05 — Guardian and human control

Open Protection. Show the actual persisted cases if seeded into the connected account, and the document quarantine warning. Explain that the current uploads remain unscanned and that OCR is blocked until a real scan/parser path exists. This honesty is part of the security architecture. No dispute is sent automatically.

### 2:05–3:10 — Meta AI as a bounded cognitive layer

From the actual user path, create an INR account and upload a statement with explicit transaction treatments. Show the import batch result and freshly computed report. Then open AI intelligence, review the separate consent for `financial_summary` and `household_obligations`, grant it and ask Muse Spark to explain a deterministic finding. Show the actual model ID, Standard mode and structured result. Explain that the request is minimized: aggregate values and generated finding descriptions only; no raw transactions, account IDs, identity, contact or document bytes. Show that unknown finding IDs are rejected and the model has no tools or mutation privileges.

### 3:10–3:40 — The wider economic system

Quickly show Opportunity, Entitlements, One-Person Enterprise and Commons. These screens intentionally label their examples as synthetic previews. Explain the target flow: capabilities + verified demand, source-grounded eligibility, unit economics, collective demand and explicit approval.

### 3:40–4:00 — System thesis

MAKOS is the user cockpit. GENIEA will provide durable, checkpointed missions. KRN will bind evidence, knowledge and temporal provenance. Deterministic services own money, permissions, eligibility and verified outcomes. Muse models supply multimodal understanding and structured reasoning. The goal is a measurable real-world economic outcome, not an impressive agent conversation.

## Rubric mapping

| User-provided judging category | Demo proof |
|---|---|
| Real-world impact, 30% | private first-user report, no network prerequisite, Guardian/essential-cost and income-opportunity problems |
| Meta AI tooling, 25% | real Muse Spark Standard call, structured JSON, minimized data and deterministic post-validation |
| Technical depth, 20% | exact-paise rules, consent, owner scope, audits, synthetic scenario tests, safe refusal and UI/API separation |
| Demo, 25% | coherent flow from one person to the wider system, with visible operational truth and no fake live actions |

## What not to claim

Do not call a synthetic report a real user outcome. Do not call the current Guardian intake OCR. Do not call a fixture match a job, scholarship, quote, settlement or payment. Do not imply that Muse Glimmer, SAM 3.1 or Voice Transcribe is integrated unless there is an actual working, tested path. Do not claim formal differential privacy from a minimum cohort size. Do not describe the prototype as production-ready.
